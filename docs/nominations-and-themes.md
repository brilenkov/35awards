## 3. Как интегрировать в текущую концепцию

### 3.1. Не смешивать номинации и темы

Оставить три сущности:

1. **Конкурс** — 11th, 10th, 12th и т.д.
2. **Номинация** — 24 основных категории.
3. **Тема** — тематический конкурс: Red Color, Nature Under Snow, Black and White Female Portrait и т.д.

Тема — не номинация. У неё другой жизненный цикл, другой ID и часто другая логика отбора. Но обе сущности ссылаются на одни и те же фотографии по `photo_id`.

### 3.2. Использовать `contests` из API как готовые связи

API `author/photodata` уже возвращает для каждого фото список конкурсов:

```json
{
  "name": "Black Color",
  "badge": "TOP 8%",
  "contest_id": "868",
  "under_id": "1103",
  "link": "https://35awards.com/page/contests/num/868/"
}
```

Сейчас pipeline сохраняет только `label` и `contest`. Нужно расширить `ContestEntry` полями `contest_id`, `under_id`, `pcp_id`, `link`, `type` (`nomination` / `theme`). Тогда:

- темы появляются в карточке фото без отдельного скрейпа;
- можно строить страницы тем из работ, которые уже есть в каталоге;
- можно показывать «Также участвовала в: Black Color · TOP 8%» со ссылкой на тему.

### 3.3. Три источника тематических коллекций

1. **Участие в тематическом конкурсе** — из API `contests` (`link` содержит `/page/contests/num/`).
2. **VLM-фасеты** — цвет, сезон, погода, монохром, жанр. Позволяет находить «красное», «снег», «ч/б» даже среди фото, которые не подавались в тематический конкурс.
3. **Результаты тематического конкурса** — отдельный парсер страницы `/page/contests/num/<id>/`: там другой HTML (`grid-item` + `openPhoto`, без `captions`), но те же `photo_id`. Это даёт полный топ темы, а не только пересечение с нашими номинациями.

В UI тема может показывать две секции:

- **Участники конкурса** — работы с бейджем этой темы.
- **Похожие по разбору** — работы из других номинаций, у которых VLM-фасеты совпали (например, «снег» или «красный акцент»).

### 3.4. Расширить VLM-фасеты

Сейчас есть `light`, `color`, `technique`, `image`, `emotion`, `season`, `focal`. Для тем нужно добавить:

- `subject`: portrait, nature, urban, animal, still-life, reportage, macro, aerial, underwater, architecture, transport.
- `accent_color`: red, white, black, golden, pink, blue, green, purple, orange.
- `weather`: snow, rain, fog, clear, storm.
- `time_of_day`: day, night, golden-hour, blue-hour.
- `monochrome`: true/false (или оставить в `color`).

Это сразу закрывает запросы «чб фото», «красный цвет», «природа под снегом» без ожидания, пока мы скачаем все тематические конкурсы.

### 3.5. Фильтры на главной

Добавить в панель фильтров:

- **Тип:** номинация / тема / всё.
- **Тема:** Red Color, Nature Under Snow, Black and White, Night City и т.д.
- **Предмет:** портрет, природа, город, животные, предметы.
- **Акцентный цвет:** красный, белый, чёрный, золотой, синий...
- **Погода:** снег, дождь, туман.
- **Время суток:** день, ночь, золотой час.

Фильтры должны работать как пересечение, как сейчас.

### 3.6. Структура папок

```
catalog/
├─ nominations/
│  └─ female-portrait/
│     ├─ 11th/
│     └─ 10th/
├─ themes/
│  ├─ red-color/
│  │  └─ 1086/
│  ├─ nature-under-snow/
│  │  └─ 1090/
│  └─ black-and-white-female-portrait/
│     └─ 1078/
└─ data/
   ├─ nominations.json
   └─ themes.json
```

Темы не должны лежать внутри номинаций: одна и та же тема может пересекаться с несколькими номинациями.

### 3.7. Приоритет внедрения

1. **Сначала 24 основные номинации за 11th и 10th.** Это даст полный срез по жанрам: ч/б, пейзаж, дикая природа, макро, мужской/детский портрет, street, fashion, nude.
2. **Затем завершённые темы.** Начать с тех, что чаще всего дают бейджи в наших фото: Black Color, Female studio portrait, Perfect Portrait, Female Portrait with Flowers, Black and White Female Portrait, Red Color, Nature Under Snow.
3. **Затем VLM-фасеты и «похожие».** Это позволит собирать темы даже там, где тематический конкурс ещё не завершён.
4. **Активные и будущие темы** добавлять в отдельный блок «Скоро» и не включать в архив до публикации результатов.

## 4. Про фильтр «Рембрандт»

Фильтр — это точное совпадение значения в `facets.light` из `analysis/analyses.json`. Это не метаданные 35AWARDS, а моя ручная/VLM-разметка.

Фото `12868266` попало в «Рембрандт» потому, что я разметил его как `["studio", "soft", "rembrandt"]`. По факту свет там петлевой (loop): тень от носа образует мягкую петлю, а классического треугольника под глазом на теневой стороне нет.

Исправлено:

- в `config/facets.json` добавлен пункт **«Петлевой (loop)»**;
- `12868266` и ещё пять похожих студийных портретов переразмечены в `loop`;
- в `analysis/analyses.json` обновлены описания света;
- после пересборки фильтр «Рембрандт» даёт **0 работ**, фильтр «Петлевой (loop)» — **6 работ**.

Чтобы такая путаница не повторялась, стоит зафиксировать в `analysis/README.md` строгие определения:

- **Rembrandt** — треугольник света на щеке теневой стороны под глазом.
- **Loop** — небольшая тень-петля под носом, без треугольника.
- **Split** — одна половина лица освещена, вторая в тени.
- **Butterfly** — симметричная тень под носом, свет по центру.
- **Short / broad** — свет со стороны, повёрнутой к камере или от камеры.

И при разметке хранить не только тег, но и уверенность (`high` / `medium` / `low`), если нужно отделять спорные случаи.
